Resource profile


Efficiency, measured here (plugged in, bench/ENERGY.md): Qwen3-1.7B decoding 0.27 tokens/J NPU only vs 0.25 Assisted (a tie); reading prompts 2.4 tokens/J NPU only vs 8.1 Assisted (5x faster). Qwen3.5-2B: 0.19 tokens/J at 0% and 25% GPU share (25% is 26% faster), 0.12 at 50%. Whole-machine watts (APU + GPU), screen not included.
Assisted profile only; applied the next time you Load a model. The KV cache of the window must fit in the GPU memory left after the weights (Qwen3-1.7B: ~114 KB per token, so ~9k tokens in 5.5 GB; the hybrid Qwen3.5 models need ~12 KB per token). The window is cut to what fits and the model state shows the real size. Without the GPU the window is 4096 tokens. GPU share: the GPU computes that fraction of the rows of every Qwen3.5 layer matrix at the same time as the NPU (faster, but the GPU works and draws power; 0% keeps the NPU as the only worker of the weights). It needs NPU kernels built for the share (the System check tells you the command).

Folders that may be read

One folder per line. Write ~ for your whole home, or e.g. ~/Documentos. Hidden folders (.ssh, .config…), keys, .env, passwords, .git, build folders and more are always skipped. After changing this, press “Index now”.

Web search

Only your question text is sent to the search provider. The server refuses to fetch anything that points to your local network.

Routing (Auto mode)

Words that decide where a question goes: history (about this chat), fresh (needs the web), terminal (use local docs), programming (answer directly). Each entry is a regular-expression fragment matched as a whole word. With classifier on, the local model decides when no rule matches (costs about a second).

Cloud assist (your own API key)

Optional, per message. Works with any OpenAI-compatible endpoint (NVIDIA NIM / Nemotron, OpenRouter, Ollama…) or Gemini. Keys are stored only in ~/.config/npu-lab/providers.json (readable by your user only) and are never shown again.
Advanced: custom endpoint, several providers
