Measured efficiency on this machine

Qwen3-1.7B decoding: 0.33 tokens/J NPU only vs 0.30 Assisted (Assisted is 11% faster); reading prompts: 3.8 tokens/J NPU only vs 33.8 Assisted (21× faster). Qwen3.5-2B decoding: 0.26 tokens/J at 0% GPU share, 0.30 at 25% (+18% speed), 0.35 at 50% (+53% speed).

How these limits work

Assisted profile only; applied the next time you Load a model. The KV cache of the window must fit in the GPU memory left after the weights (Qwen3-1.7B: ~114 KB per token, so ~9k tokens in 5.5 GB; the hybrid Qwen3.5 models need ~12 KB per token). The window is cut to what fits and the model state shows the real size. Without the GPU the window is 4096 tokens.

GPU share: the GPU computes that fraction of the rows of every Qwen3.5 layer matrix at the same time as the NPU (faster, but the GPU works and draws power; 0% keeps the NPU as the only worker of the weights). It needs NPU kernels built for the share; the System check tells you the command.

Defaults: 2B 50%, everything else 0%. 2B at 75%: +34% decode speed over 50% (18.2 vs 13.6 tok/s), but the whole machine draws ~60 W instead of ~44 W and tokens/J stays ~0.30 (bench/ENERGY.md). 4B at 25%: +18% speed, but the GPU memory peak is 5277 MiB and CUDA can use 5857 MiB of the 6144 (about 580 MiB left for the desktop; 0% leaves about 800 MiB), so with the default 700 MiB margin the 4B only loads at 0% unless you lower the margin. Shares are per model; the list only offers those with a measured fit.
